<summary>
- A `spec.type: service` Config can now name the namespace its StatefulSet lives in, instead of being pinned to the executor's own namespace by the reconciler's constructor.
- An unset namespace means "the executor's own namespace", so `claude-interactive` and `pi-interactive` behave exactly as they do today and the deploy is a no-op.
- A Config that explicitly names the executor's own namespace is rejected by the same rule that already governs `JobNamespace`, so no Config can be written to opt out of isolation.
- The executor's own Kubernetes schema declares the new field, so the API server does not silently prune it.
- The value survives the resolver: a Config with the field set reaches the reconciler with it set, and an unset field reaches it empty.
- `UndeployService` gains the resolved namespace, because a delete aimed at the executor's namespace leaves the moved StatefulSet running while reporting success.
- No namespace, policy, RBAC or ingress is created here — that stays in the `bborbe/agent` chart.
</summary>

<objective>
Add `ServiceNamespace` to the Config CRD type and to `AgentConfiguration`, declare it in the binary's own CRD schema, carry it through `convert()`, add the pure derivation rule `ResolveServiceNamespace`, and make `ServiceReconciler` resolve and use it for both create and delete. End state: a Config's `spec.serviceNamespace` survives the whole path from API object to the StatefulSet's namespace, and an unset field leaves every existing object byte-identical.
</objective>
