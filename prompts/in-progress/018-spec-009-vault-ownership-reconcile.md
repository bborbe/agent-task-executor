# Switch reconcile and task ownership onto the in-memory task view

<summary>
- Each reconcile pass now reads a point-in-time snapshot of the in-memory task view instead of listing and fetching vault files
- A pass over fifteen thousand tasks becomes an in-memory scan and completes well under one second
- A pass before the view is ready drives nothing and is counted as a distinct not-ready outcome
- Task ownership becomes a plain comparison between the task's stamped vault and a new `TASK_VAULT` setting
- The setting defaults to `VAULT_NAME`, is validated at startup, and does not change how agent Configs are resolved
- A task with no stamped vault is never owned, and a view in which every task is unstamped fails loudly instead of idling
- A view that holds tasks but none from this executor's vault fails loudly on every pass, naming the vaults it saw
- The same ownership rule gates the live event path and the reconcile path, replacing the old path-derived ownership set
- A deferral that finds no queue timestamp on the incoming event takes it from the view, preserving duplicate-event protection
- The reconcile outcome metric gains the new outcomes and loses the git-rest ones, and the pass summary line reports the task vault
</summary>

<objective>
Make the reconcile floor read the in-memory task view built by the previous prompt, and replace path-derived task ownership with a `Task.Vault == TASK_VAULT` comparison on both the live event path and the reconcile path. git-rest code still compiles after this prompt; only its use by reconcile and ownership is removed.
</objective>
