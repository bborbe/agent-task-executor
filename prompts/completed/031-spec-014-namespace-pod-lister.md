<summary>
- A Job's pod detail is now read from the cache of the namespace the Job actually runs in, so a sandbox Job is no longer classified from the executor's cache.
- Asking for a namespace's pod cache returns that namespace's cache, or nothing when that namespace has not finished starting.
- A namespace that has not finished starting makes the sweeper skip that one task instead of reporting a false failure from the wrong cache.
- The sweeper works out each task's namespace from the Configs it already reads every tick, and falls back to the executor's own namespace when the task's assignee matches no Config.
- When two Configs share an assignee, the first match still wins, so which namespace a task resolves to does not change.
- Existing failure reporting, task cleanup, and pod-state classification are untouched.
- The generated test fake is rebuilt from the interface rather than edited by hand, and the existing tests keep passing.
</summary>

<objective>
Make `JobWatcher.PodLister` take the namespace whose lister is wanted, wire both consumers to the Job's or task's namespace, and update the zombie sweeper to resolve a task's namespace from the Configs with the executor-namespace fallback. End state: a Job in a sandbox namespace is classified from that namespace's Pod cache, and the sweeper never reads the executor's cache for a sandbox task.
</objective>
